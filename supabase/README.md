# Supabase backend

Проект: `challenge-30-days` (`pszeugqdnudbherkpjwx`, регион eu-central-1).

## Как это устроено

Всё общение идёт через одну функцию `sync_state`:

- она принимает изменённые записи с телефона, применяет их **по одной записи**
  по правилу «побеждает более поздняя», и возвращает полное текущее состояние;
- сравнение идёт по `updated_at` каждой строки, поэтому два телефона,
  сохраняющие одновременно, не могут затереть данные друг друга;
- входящие метки времени ограничены сверху (`clamp_ts`), чтобы телефон со
  сбитыми часами не заблокировал записи партнёра навсегда.

## Про ключ в бандле

Ключ `anon` лежит в публичном JS — так и задумано, это не секрет. Поэтому
таблицы закрыты: RLS включён, политик нет, гранты сняты. Прямой доступ к
таблицам по этому ключу возвращает 401. Единственная доступная операция —
вызов `sync_state`, у которого ограничен размер запроса.

Это **не** аутентификация: любой, кто достанет ключ из бандла, сможет читать и
менять состояние челленджа. Для двух человек это осознанный компромисс. Полноценная
защита потребует проверки Telegram initData в Edge Function с токеном бота.
